# Выбранное направление

> 23.10.2026. Решение по итогам [разбора вариантов](product-options.md).

## Вводные владельца

- Open source ради портфолио, без заработка.
- Никакой зависимости от Apple, Microsoft, Google и их релизных политик.
- Компании и отдельные приложения встраивают продукт в свой процесс выпуска.
- Бюджет нулевой, время не ограничено.

Из пяти вариантов под эти вводные подходит **вариант 4 (открытый стандарт) вместе с ядром варианта 1 (SDK)**, но без облачного сервиса: всё разворачивается у того, кто внедряет.

## Что это за продукт

**Self-hosted слой каналов стабильности для любого приложения.** Компания поднимает сервер у себя, подключает SDK и получает:

1. **Каналы.** Пользователь сам выбирает уровень. По умолчанию их 3 (ранний, обычный, спокойный), но число задаётся в конфиге, так что 7 тоже возможны.
2. **Договор канала.** На раннем уровне включены автосбор ошибок по согласию и «пульс» в один клик после обновления. Кто неактивен, тот переводится на уровень ниже.
3. **Здоровье по каналам.** Ошибки, пульсы и отчёты собираются по каждой функции и каждому каналу.
4. **Гейты продвижения.** Функция переходит в следующий канал, когда выполнено правило в духе Fedora Bodhi: N дней в канале, нет красных пульсов, ошибок не больше, чем у базовой версии. Решение принимает сервер или CI.

## Как обойти зависимость от платформ

Каналы работают **на уровне функций внутри приложения, а не на уровне сборок в магазине**. Все пользователи ставят одну и ту же сборку, а SDK решает, какие функции включены для их канала. Поэтому:

- на iOS и Android не нужны TestFlight, треки Play и правила бета-тестирования магазинов. Включение уже встроенного кода через удалённую конфигурацию — обычная практика (так работают все фича-флаги). Скачивать и исполнять новый код при этом нельзя, и SDK этого не делает;
- на вебе, бэкенде и десктопе ограничений нет вообще;
- каналы на уровне сборок (бинарные обновления) остаются опцией для десктопа через адаптеры к electron-updater или Tauri, но они не обязательны.

Сервер работает у компании, поэтому данные пользователей не уходят к третьей стороне. Это заодно снимает с автора вопросы 152-ФЗ и GDPR: оператором данных остаётся тот, кто развернул сервер.

## Как встраиваться в чужой процесс

Главное правило: не делать «ещё одну систему флагов», а встраиваться в те, что уже есть.

- **OpenFeature-провайдер.** Команда, у которой уже есть Unleash, Flagsmith, GrowthBook или свои флаги, подключает каналы как слой поверх них, без переезда.
- **Встроенное хранилище флагов** для тех, у кого флагов нет.
- **CLI и HTTP API** для CI: `promote`, `status`, `rollback`. Отдельный GitHub Action — тонкая обёртка над CLI, а не обязательная часть.
- **Веб-компонент** с переключателем канала, пульсом и формой отчёта. Подходит любому фронтенду (Shadow DOM), его можно заменить своим интерфейсом через SDK.
- **Экспорт событий** (webhook, OpenTelemetry) в Sentry, Grafana и трекеры задач.

## Чем отличается от существующего open source

| Проект | Что есть | Чего нет |
|---|---|---|
| Unleash, Flagsmith, GrowthBook, flagd | Флаги, сегменты, процентные раскатки | Канала, который выбирает сам пользователь, договора канала, гейтов по сигналам пользователей |
| PostHog | Пользователь сам включает бета-функции (только JS Web SDK) | Уровней, обязанностей, гейтов. Большая платформа, которую неудобно брать ради одной функции |
| Fedora Bodhi | Карма и автоматическое продвижение | Работает только для пакетов Fedora |

## План

Сроки рассчитаны на работу в одиночку в спокойном темпе.

| Этап | Срок | Результат |
|---|---|---|
| 0. Спецификация | 1–2 недели | README с концепцией, спецификация (модель каналов, договор, правила гейтов, API), ADR по ключевым решениям, лицензия |
| 1. Ядро | 4–6 недель | Сервер (TypeScript, SQLite по умолчанию, Postgres опционально), Docker-образ, JS SDK, веб-компонент, OpenFeature-провайдер, дашборд |
| 2. Гейты и CI | 3–4 недели | Правила продвижения, CLI, GitHub Action, метрики здоровья по каналам |
| 3. Расширение | дальше | Flutter SDK, адаптеры для electron-updater и Tauri, экспорт в OpenTelemetry |

**Обкатка на себе.** Первым внедрением станут аркадные игры и сайт `usertrv.dev`: настоящий процесс выпуска, на котором видно, как продукт работает.

**Демо без бюджета.** Статическая страница на GitHub Pages: сервер работает в браузере (in-memory или SQLite в WASM), посетитель переключает каналы и видит, как функции продвигаются. VDS не трогаем: на нём VPN, а памяти всего 1 ГБ.

## Ценность для портфолио

- Архитектура и дизайн API: спецификация, SDK, расширяемость через OpenFeature.
- Angular-дашборд — твоя основная экспертиза — и встраиваемый веб-компонент.
- Документация уровня зрелого OSS: ADR, руководство по внедрению, threat model.
- Темы для доклада и статьи на Хабре: «почему не 7 каналов», «гейты продвижения по сигналам пользователей».

## Как понять, что идём правильно

Звёзды на GitHub — слабый сигнал. Сильные сигналы:

1. 3 внешние команды или OSS-проекта прочитали спецификацию и сказали, что внедрили бы или что им мешает. Это стоит собрать до этапа 1.
2. Хотя бы одно внедрение вне `usertrv.dev` к концу этапа 2.
3. Внешние issue и PR.

## Открытые решения

- **Лицензия.** Предлагаю Apache-2.0: компании берут её спокойно, есть патентная оговорка.
- **Название.** Рабочее — release7.
- **Стек сервера.** Предлагаю Node.js и TypeScript, чтобы держать один язык с SDK и дашбордом.
